## 1. 引言

### 1.1 编写目的
描述"学校教学管理系统"当前版本的功能边界、行为规则与验收标准，作为研发实现对照与测试用例设计依据。每条功能需求均可追溯至具体代码文件。

### 1.2 项目范围

**包含：**
- 后端（`cn\jelly\`）：学生、教师、课程、班级、排课、选课与成绩 6 个数据管理模块 + 首页统计接口，共 7 个路由分组 35 个 HTTP 接口；
- 前端（`static\`）：管理框架页（分组菜单 + 面包屑 + iframe 内容区）、首页数据看板、7 个功能页面；
- 通知公告：**纯前端模块**，浏览器 localStorage 模拟数据，无后端接口。

**不包含（当前代码中不存在）：**
- 登录认证、角色权限（全源码无任何 auth 相关代码）；
- 业务审计日志、数据备份恢复、生产部署方案、自动化测试 → [待补充]

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| 统一响应 | 所有接口 HTTP 状态恒为 200，以 body `{"code": 整数, "msg": 文本, "data": ...}` 区分成败：`0` 成功、`1` 通用失败、`1000` 资源不存在（NOT_EXIST）、`500` 系统异常（common\response.py、common\exceptions.py） |
| BizException | 业务异常。service 层抛出，api 层捕获后转统一失败响应，HTTP 仍为 200 |
| 当前学期 | 服务端按日期计算，格式 `学年-学年-序号`（如 2026-2027-1）：月≥8 → `y-(y+1)-1`；月=1 → `(y-1)-y-1`；月 2~7 → `(y-1)-y-2`（cn\jelly\arrangement\service.py `get_current_term()`） |
| 伙伴服务 | 独立部署的 cn_obj 服务 `http://127.0.0.1:8002`，仅"按教师查学生"的详情接口调用，超时 5s（common\config.py） |
| js-dd | 自定义下拉组件（static\js\common.js `initDropdowns`）：隐藏原生 select 保留表单取值/ reset 逻辑，外层渲染带打开动效的下拉按钮与菜单 |
| 内容区 | 框架页右侧 iframe（#contentFrame），菜单切换时加载 `/static/html/<模块>/index.html` |
| 前端分页 | 教师模块后端仅提供全量列表（/teacher/list），分页由前端过滤与切片实现 |

### 2.1 产品愿景
为学校教学场景提供学生、教师、课程、班级、排课、选课与成绩的一站式管理（源自 FastAPI 应用描述 "use management system to manage students and teachers modules"），并以数据看板呈现全局统计与当日课表。业务愿景与产品路线图 [待补充]。

## 3. 功能需求

> 优先级：**高** = 核心流程，缺失不可用；**中** = 重要辅助；**低** = 体验增强（PM 判定）。
>
> 通用规则（适用于所有 CRUD 模块，各表不再重复）：
> - **R1** 分页接口返回 `{total, page, size, rows}`；service 层将 page 收窄至 ≥1、size 限制在 1~100（MAX_PAGE_SIZE）
> - **R2** 查询/修改/删除不存在的记录 → `code=1000`（NOT_EXIST）
> - **R3** 必填缺失、超长、数值越界 → FastAPI 返回 HTTP 422，前端弹窗提示且不提交
> - **R4** 前端写操作经 common.js `api()` 调用：code≠0 时 toast 提示且列表不刷新

### 3.1 学生管理（cn\jelly\student\，页面 static\html\student\index.html）

| 需求编号 | 功能名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-STU-01 | 学生分页查询 | 高 | GET /student/page，keyword 按姓名模糊匹配 | 返回 total/page/size/rows；keyword="张" 仅返回姓名含"张"的记录；size=200 实际按 100 返回 |
| FR-STU-02 | 新增学生 | 高 | 字段：姓名(1~50)、性别(man/woman)、年龄(1~100)、任课教师(下拉，选项=全部教师 "id - 姓名")、年级(高一/高二/高三)、入学日期(选填)。新增前校验教师存在 | 传入不存在 teacher_id → `code=1000, msg=任课老师不存在`；合法提交后列表刷新且新纪录可见 |
| FR-STU-03 | 修改学生 | 高 | 先查详情回填弹窗（GET /student/{id}），校验同新增 | 修改后列表即时更新；不存在 id → code=1000 |

| FR-STU-05 | 学生全量列表 | 中 | GET /student/list，供其他模块下拉/统计引用 | 返回全部学生记录 |

## 4. 非功能需求

| 类别 | 编号 | 需求描述 | 验收标准 / 来源 |
|---|---|---|---|
| 性能 | NFR-P1 | 列表查询均为服务端分页，size 上限 100（MAX_PAGE_SIZE），非法分页参数自动收窄 | size=200 时返回 rows ≤ 100（common\config.py、各 service.py） |
| 性能 | NFR-P2 | 数据库连接经 DBUtils PooledDB 连接池复用（缓存 5/5、最大 10、单连接复用 ≤1000 次、ping=1、blocking=True） | 连接参数见 common\pool.py；并发请求不新建超量连接 |

## 5. 约束与假设

1. **数据库脚本手动执行**：`cn\jelly\` 下仅 4 个建表脚本（subject.sql、clazz.sql、arrangement.sql、enrollment.sql），需在 `school_db` 库手动执行；依赖顺序为 teacher/student（基础表）→ subject → clazz → arrangement/enrollment。
2. **student、teacher 两张基础表无 DDL 脚本**，表结构仅能从 dao.py 反推（student：name/gender/age/teacher_id/grade/enrollment_date；teacher：name/gender/age/subject/phone）→ 建表脚本 [待补充]。
3. **重复执行风险**：subject/arrangement/enrollment 脚本先 DROP 再 CREATE（会清空数据）；clazz 为 CREATE IF NOT EXISTS；各脚本 INSERT 段重复执行会重复插入数据。
4. **通知公告数据仅存浏览器 localStorage**：清缓存、换浏览器/设备即重置为内置 3 条模拟数据，多端数据不互通（设计行为）。
5. **上课时间为自由文本**（如"周一 1-2节"），"今日排课"按文本包含"周X"匹配当天星期，不解析节次/日期，跨天课程无法表达。
6. **教师详情接口存在外部依赖**：GET /teacher/{id} 调用伙伴服务 `http://127.0.0.1:8002`（超时 5s），伙伴服务未启动时该接口返回业务失败；GET /teacher/{id}/detail 为本地组装，不受影响。
7. **学期计算规则固定**于服务端（见 1.3 术语），前端不传学期即由服务端填充。
8. **日志文件路径相对启动目录**（`../user information.log`），从不同工作目录启动会写入不同位置。
9. 无单元测试/集成测试代码，无 CI/CD 与生产部署方案 [待补充]。
10. 假设系统为**校内单机小规模使用**（无并发压力指标），性能指标量化目标 [待补充]。
